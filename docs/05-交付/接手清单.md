## 六之二、退款与配送的日常操作（后台怎么用）

> 这两块是**业务闭环的最后两环**，接手人每天都会用到。

### 退款单（后台 → 退款单）

**流程：**

```
用户在售后里申请退款
  ↓ 系统自动校验 5 条规则（订单状态/金额/重复/时效）
创建退款单（状态=待审核）
  ↓
后台 → 退款单 → 看到待审核的单子
  ↓ 点「通过」或「拒绝」
通过 → 自动调支付网关退款
  ├→ 成功：状态变「已退款」，记录网关流水号
  └→ 失败：状态变「退款失败」，记了原因，可点「重试」
```

**审核时可以：**
- 调整金额（传 `adjusted_amount`，比如只退部分）
- 拒绝必须填理由

**注意：** 接的是 Mock 支付时，退款**立即成功**（不真退钱）。接真网关后行为由网关决定，业务代码不用改。

### 配送管理（后台 → 配送管理）

**看什么：**
- 订单号、履约方（Mock / 顺丰 / 达达…）、状态、外部单号、推送时间
- 状态是中文：待推送 / 已推送 / 已接单 / 配送中 / 已送达 / 推送失败

**能做什么：**
- 推送失败或待推送的单子，点「**重推**」
- 状态不对（比如已送达）时不允许重推，会提示

**和订单状态的联动（重要）：**

```
订单已支付
  ↓ 推履约（后台或自动）
订单自动变「配花中」
  ↓ 履约方回调 status=delivering
订单变「配送中」
  ↓ 履约方回调 status=delivered
订单变「已送达」
```

**如果履约方没回调**，可以在「订单/待处理」里手动点「推进」。

## 七、第六步：接外部服务（按需）

### 支付（必须接，否则收不了钱）

**当前状态：Mock，模拟收银台，点一下"支付成功"就到账。**

> **接真网关（微信/支付宝）、接第三方配送（顺丰/达达/闪送）、接短信/OSS/Redis 的完整步骤、参数映射、工作量对照，都写在：**
> **`docs/02-技术/第三方接入说明.md`**
> 接手人先读那份，再回来做本节。

**要接真实支付：**

1. 申请微信支付商户号（需要营业执照 + 对公账户 + ICP 备案）
2. 装 SDK
3. 新建 `backend/app/adapters/payment/wechat.py`，实现 `BasePayment` 接口
4. 改 `.env`：
   ```ini
   PAYMENT_PROVIDER=wechat
   WECHAT_PAY_MCH_ID=...
   WECHAT_PAY_APP_ID=...
   WECHAT_PAY_KEY=...
   ```

**代码里留了接口，照着 `mock.py` 的结构写就行。**

### 短信（要真发验证码就接）

**当前状态：Mock，验证码打到日志 + 前端自动填入。**

**要接真实短信：**

1. 阿里云控制台申请「签名」+「模板」，审核 1-2 天
2. 装 SDK：`pip install alibabacloud_dysmsapi20170525`
3. 补 `backend/app/adapters/sms/aliyun.py` 里的 TODO（约 20 行）
4. 改 `.env`：
   ```ini
   SMS_PROVIDER=aliyun
   ALIYUN_SMS_KEY_ID=...
   ALIYUN_SMS_KEY_SECRET=...
   ALIYUN_SMS_SIGN_NAME=...
   ALIYUN_SMS_TEMPLATE_CODE=...
   ```

### 文件存储（多台服务器必须接）

**当前状态：本地磁盘 `backend/storage/uploads/`，单机可用。**

**多机部署要接 OSS：**

1. 阿里云开 Bucket，设为公共读
2. 装 SDK：`pip install oss2`
3. 补 `backend/app/adapters/storage/oss.py` 里的 TODO（约 10 行）
4. 改 `.env`：
   ```ini
   STORAGE_PROVIDER=oss
   OSS_ENDPOINT=...
   OSS_BUCKET=...
   OSS_ACCESS_KEY_ID=...
   OSS_ACCESS_KEY_SECRET=...
   OSS_PUBLIC_URL=...
   ```

### 缓存（生产环境必须接）

**当前状态：内存，验证码重启就丢，多进程不共享。**

**生产环境必须换 Redis：**

1. 装 Redis
2. 装 SDK：`pip install redis`
3. 改 `.env`：
   ```ini
   CACHE_PROVIDER=redis
   REDIS_URL=redis://127.0.0.1:6379/0
   REDIS_PASSWORD=...
   ```

**代码已经写好了，不用改。**

## 八、第七步：上线部署

### 1. 域名 + 备案

**ICP 备案 7-20 天，这是最长的环节，尽早开始。**

### 2. 服务器

**2 核 4G 起，装 Python 3.11 + PostgreSQL 18 + Redis。**

### 3. Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名.com;

    # 前端静态文件（直接托管）
    location / {
        root /var/www/twl/frontend;
        try_files $uri $uri/ /index.html;
    }

    # 后端接口
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 用户上传
    location /uploads/ {
        alias /var/www/twl/backend/storage/uploads/;
    }
}
```

### 4. systemd

```ini
[Unit]
Description=Tiao Wu Lan Backend
After=network.target postgresql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/twl/backend
Environment="PYTHONUTF8=1"
ExecStart=/var/www/twl/backend/.venv/bin/gunicorn app.main:app \
    -w 4 -k uvicorn.workers.UvicornWorker --bind 127.0.0.1:8000
Restart=always

[Install]
WantedBy=multi-user.target
```

### 5. 生产环境必改配置

**启动时会自动检查，不合规拒绝启动：**

```ini
APP_ENV=production
DEBUG=false
SECRET_KEY=至少32位随机串
CORS_ORIGINS=https://你的域名.com
CACHE_PROVIDER=redis
SMS_PROVIDER=aliyun
```

## 十二、这套系统的设计原则

**1. 数据可以 demo，承诺不能 demo**
示例商品、示例价格可以，但「2 小时达」这种服务承诺不能编。

**2. 能配置的不要写死**
配送规则、公告、联系方式全部从数据库读，改配置不改代码。

**3. 外部服务全部适配器**
支付、短信、存储、缓存都抽成接口，改 `.env` 就能换实现。

**4. 演示数据可一键清空**
所有测试数据打 `is_demo` 标记，`reset_demo.py` 一键删。

**5. 路径全部相对**
项目挪到任何位置都能跑，不依赖绝对路径。
