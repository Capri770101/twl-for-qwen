文档规范

以后加文档按这个来。
1
只留有效的
中间态（整改过程、版本对比）、测试态（一次性测试报告）不进 docs。内容并入正式文档，原文件删掉
2
归到对的分类
需求 → 01 · 技术 → 02 · 交付 → 03 · 原型 → 04 · 背景 → 根目录
3
格式选择
需求和工程 → .md（能 diff、好改）；交付和原型 → .html（能带样式、好读）
4
中文命名
项目状态总结.html 比 status_v2.html 好。直接说清楚是什么，不搞缩写
5
改了就改，别留副本
文档没有「版本 2」，直接改原文。历史在 git 里，不靠文件名
