## 一、改版目标

| 目标 | 达成方式 |
|---|---|
| 首屏要有品牌质感，不能是一堆文字 | 换成 21:9 通栏实景图作背景 |
| 导航要干净，不像传统电商那样一层层堆 | 导航与「联系/登录」合并成一行 |
| 品牌名不能被导航栏挤在中间 | Logo 移到图片右上角 |
| 宽屏不能左右留白 | 头图真正通栏 |

## 三、CSS 关键点

### 3.1 图片作背景，文字叠上层

```css
.hero-img{position:relative;overflow:hidden;min-height:clamp(440px,64vh,780px)}
.hero-bg{position:absolute;inset:0;width:100%;height:100%;object-fit:cover;object-position:center 42%;z-index:0}
.hero-inner{position:relative;z-index:1}
```

`object-position` 决定取景：桌面 `center 42%`（花在右侧、上方留白给文字），移动端 `62% 48%`（竖屏只看得到横图中间一条，右移到花上）。

### 3.2 头图通栏

`.hero` 同时挂在两个 `max-width` 列表里（1320 / 1520），宽屏上会左右留白。单独开一个口子：

```css
.hero.hero-img{
  max-width:none !important;
  width:100% !important;
  margin-left:0 !important;
  margin-right:0 !important;
}
```

用 `.hero.hero-img` 双类选择器提高特异性，避免去动那一大串共享规则。

### 3.3 导航与联系/登录同一行

```css
.hd-bar{position:relative;display:flex;align-items:center;justify-content:center;min-height:54px}
.hd-top{position:absolute;right:24px;top:50%;transform:translateY(-50%)}
```

导航靠 `.hd-bar` 的 `justify-content:center` 居中，「联系/登录」用绝对定位钉在右侧，两者垂直中线对齐。

移动端 390 宽放不下 8 个词，改成「导航横滚 + 右侧固定」：

```css
@media (max-width:768px){
  .hd-nav{flex:1;min-width:0;overflow-x:auto}
  .hd-top{position:static;transform:none;flex:0 0 auto}
}
```

### 3.4 Logo 压在图上要能读

图片右上角是窗框亮部，深色字仍然要清楚，所以加白晕：

```css
.hero-logo .logo{
  color:#1a1a1a;
  text-shadow:0 1px 16px rgba(255,255,255,.95), 0 0 34px rgba(255,255,255,.7);
}
```

## 四、踩过的坑

### 4.1 演示提示条盖住页面顶部

**现象**：移动端「联系/登录」怎么都看不到。

**根因**：`api.js` 里给 body 预留的空间写死 34px，但提示条在窄屏会换行，实际高 55px，正好把 21px 高的按钮压掉。

**修法**：

```js
const reserve = () => { document.body.style.paddingTop = bar.offsetHeight + "px"; };
reserve();
window.addEventListener("resize", reserve);
```

**影响范围**：全站，不止首页。

### 4.2 导航把 header 撑到 504px

**现象**：`right:14px` 的按钮落到 `x=431`，跑出 390 宽的屏幕。

**根因**：`.hd-nav ul` 的 `min-width:max-content` 让导航条保持内容宽度（约 484px），把整个 header 撑宽。

**修法**：解掉 `min-width`，交给 `.hd-nav` 的 `overflow-x:auto` 滚动。

### 4.3 `<script defer>` 导致 API 未定义

**现象**：商城页报「商品加载失败 — API is not defined」。

**根因**：

```html
<script src="js/api.js" defer></script>   <!-- 解析完成后才执行 -->
<script>API.listProducts()</script>        <!-- 立即执行，此时 API 还没定义 -->
```

**修法**：去掉 `defer`（本地 14KB 文件，同步加载影响可忽略）。

**注意**：首页没事是因为它 SSR 渲染，商品不走 JS。

### 4.4 分类筛选显示 undefined

**现象**：商城筛选按钮显示「undefined ·」。

**根因**：接口返回 `{ key: 'daily', count: 3 }`，代码读的是 `x.id`。

**修法**：

```js
const CAT_LABELS = { daily:'日常', love:'告白', birthday:'生日', sympathy:'探望' };
const id = x.id ?? x.key ?? '';
return { id, name: x.name ?? CAT_LABELS[id] ?? id };
```

同时支持 `?category=daily` 直接进入筛选状态，首页导航的「日常/告白/生日」就是指向这些。

## 五、验证方法

改完必须实际验证，不能只看代码。推荐用 Chrome DevTools Protocol 在精确视口下测量：

```js
// 390 视口下量元素位置
Emulation.setDeviceMetricsOverride({width:390,height:844,deviceScaleFactor:2,mobile:true})
Runtime.evaluate({expression:"document.querySelector('.hd-top').getBoundingClientRect()"})
```

**踩过的坑**：`chrome --headless --window-size=390,844 --screenshot` 的实际视口不是 390（会偏大到 504），CSS 按 504 布局，右上角元素跑到截图外面，看起来像"元素消失了"。**截图必须用 CDP 的 `Emulation.setDeviceMetricsOverride`，并配 `Page.reload({ignoreCache:true})` 清缓存。**
