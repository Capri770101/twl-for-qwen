# 一、设计定位

## 1.1 这是什么站

| 属性 | 权重 |
|---|---|
| **品牌官网** | 主 —— 让人记住「跳舞兰」这个名字 |
| **内容平台** | 次 —— 花语百科，负责 SEO/GEO |
| **购物渠道** | 末 —— 打通链路，不是主推 |

**设计原则：不急着卖东西。**

参照：Aoyama Flower Market（品牌站）+ 日式轻奢小众电商。

## 1.2 视觉语言

| 元素 | 规范 |
|---|---|
| 主背景 | 纯白 `#ffffff` |

# 三、用户体系

## 3.1 核心决策：不强制登录

```
游客下单 → 不拦 → 但明确告知风险
登录     → 自动认领历史订单
```

## 3.4 数据模型

```
users
├── id
├── phone            唯一身份（登录用）
├── external_id      微信 openid（预留）
├── nickname
├── avatar
├── channel          phone / wechat / guest
└── is_active

addresses
├── id, user_id
├── receiver, phone
├── province, city, district, detail
├── tag（家/公司）
└── is_default

orders
├── user_id          登录用户
├── guest_token      游客订单标识（localStorage）
└── phone            下单手机号（游客认领用）
```

## 3.5 订单认领逻辑

```python
# 用户登录时
def claim_orders(user):
    # 1. 按手机号认领游客订单
    UPDATE orders
    SET user_id = :user_id
    WHERE phone = :user_phone
      AND user_id IS NULL

    # 2. 按 guest_token 认领（同一浏览器）
    UPDATE orders
    SET user_id = :user_id
    WHERE guest_token = :guest_token
      AND user_id IS NULL
```

## 3.6 边界情况

| 情况 | 处理 |
|---|---|
| 用户换手机号 | 做换绑功能，订单不迁移 |
| 同手机号多端登录 | 同一个 user 记录 |
| 游客清缓存 | 订单失踪（所以必须提示保存订单号） |
| 未登录访问 `/account` | 跳登录，登录后回原页 |
| Token 过期 | 刷新或重新登录 |
| 微信登录无手机号 | 强制绑手机后才能下单 |

# 四、技术方案

## 4.1 渲染策略

| 页面 | 渲染 | 理由 |
|---|---|---|
| 首页 | **SSG** | 内容固定 |
| 花语百科 | **SSG** | 纯内容，SEO 最佳 |
| 商品列表 | **ISR**（60s） | 商品变化不频繁 |
| 商品详情 | **SSG + ISR** | 每商品一页，SEO 最佳 |
| 结算/订单 | **CSR** | 个性化，不需 SEO |
| 后台 | **CSR** | 内部用 |

## 4.2 SEO / GEO 落地

### 每个页面必须有

```html
<title>商品名 - 属性 | 跳舞兰</title>
<meta name="description" content="50-160 字，含关键词">
<link rel="canonical" href="...">
<meta property="og:title" content="...">
<meta property="og:image" content="...">
```

### 结构化数据

| 页面 | schema |
|---|---|
| 首页 | `Florist` + `Organization` |
| 商品详情 | `Product` + `Offer` |
| 花语详情 | `Article` + `FAQPage` |
| 常见问题 | `FAQPage` |
| 关于 | `AboutPage` |

### 站点文件

```
/robots.txt      爬虫规则
/sitemap.xml     页面清单
/llms.txt        AI 读的站点说明（GEO 核心）
```

# 五、后端补充接口

## 5.1 认证

```
POST /api/v1/auth/send-code       发验证码
POST /api/v1/auth/login           手机号登录
POST /api/v1/auth/refresh         刷新 token
GET  /api/v1/auth/me              当前用户
```

## 5.2 账户

```
GET    /api/v1/account/orders          我的订单
GET    /api/v1/account/addresses       地址簿
POST   /api/v1/account/addresses       新增
PUT    /api/v1/account/addresses/{id}  修改
DELETE /api/v1/account/addresses/{id}  删除
PUT    /api/v1/account/profile         改资料
```

## 5.3 内容

```
GET /api/v1/articles                   花语列表
GET /api/v1/articles/{slug}            花语详情
GET /api/v1/faqs                       常见问题
```

## 5.4 游客订单查询

```
GET /api/v1/orders/guest?order_no=xxx&phone=xxx
```

**必须同时提供订单号和手机号，防止被遍历。**

## 5.5 需要新增的表

```sql
CREATE TABLE articles (
    id, slug, title, summary, content,
    category, cover, tags, published_at,
    seo_title, seo_description
);

CREATE TABLE faqs (
    id, question, answer, sort_order, category
);

CREATE TABLE sms_codes (
    id, phone, code, expires_at, used
);
```
