# 第三方接入说明

**给接手的开发：真实业务环境怎么接。**

本文覆盖三块：
1. 支付 / 退款（微信、支付宝）
2. 履约 / 配送（顺丰、达达、闪送、自有团队）
3. 短信 / 存储 / 缓存

---

## 一、设计原则

**所有外部依赖都走「适配器模式」。**

```
业务代码
  ↓ 只调抽象接口
adapters/payment/base.py       ← 抽象定义
  ↓ 运行时选实现
adapters/payment/mock.py       ← 开发环境
adapters/payment/wechat.py     ← 生产环境（待写）
```

**换实现只需三步：**
1. 写一个新的 adapter 类，继承 base
2. 在 `adapters/*/__init__.py` 的工厂函数里加分支
3. 改 `.env` 里的 provider 配置

**业务代码一行不改。**

## 二、支付 / 退款

### 现状

| 项目 | 状态 |
|---|---|
| 创建支付 | ✅ Mock 实现 |
| 支付回调 | ✅ Mock 实现 |
| 验签 | ⚠️ 抽象方法有，Mock 不验 |
| **退款** | ✅ Mock 实现（立即成功） |

### 抽象接口

`backend/app/adapters/payment/base.py`：

```python
class PaymentAdapter(ABC):
    @abstractmethod
    async def create_payment(self, order_no, amount, channel, **kwargs) -> dict:
        """创建支付，返回支付参数"""

    @abstractmethod
    async def verify_callback(self, headers, body) -> bool:
        """验签。生产环境必须实现"""

    @abstractmethod
    async def parse_callback(self, body) -> dict:
        """解析回调内容"""

    async def query_payment(self, order_no) -> dict:
        """查支付状态"""

    async def refund(self, order_no, amount, reason="") -> dict:
        """发起退款"""
```

### 接微信支付

**前置条件：**
- ICP 备案完成
- 营业执照 + 对公账户
- 申请商户号（微信支付商户平台）
- 配置 API v3 密钥 + 商户证书

**要写的代码：**

`backend/app/adapters/payment/wechat.py`：

```python
class WechatPayment(PaymentAdapter):
    async def create_payment(self, order_no, amount, channel, **kwargs):
        """
        调 微信 V3 Native 下单
        POST https://api.mch.weixin.qq.com/v3/pay/transactions/native
        """
        # 参数映射
        #   out_trade_no → order_no
        #   amount.total → int(amount * 100)  # 元转分
        #   description  → 订单商品名
        #   notify_url   → https://你的域名/api/v1/payments/callback
        ...
        return {
            "prepay_id": ...,
            "pay_url": ...,      # 二维码链接
            "amount": amount,
        }

    async def verify_callback(self, headers, body) -> bool:
        """
        验证微信回调签名
        - 用平台证书验证 Wechatpay-Signature
        - 解密 resource（AES-256-GCM）
        """
        ...

    async def parse_callback(self, body) -> dict:
        """
        解析回调
        返回 {"order_no", "trade_no", "amount", "success"}
        """
        ...

    async def refund(self, order_no, amount, reason=""):
        """
        调 微信 V3 申请退款
        POST https://api.mch.weixin.qq.com/v3/refund/domestic/refunds
        """
        # 参数映射
        #   out_trade_no   → order_no
        #   amount.refund  → int(amount * 100)  # 元转分
        #   reason         → reason
        #
        # 返回值映射
        #   refund_id      → 我们记到 external_ref
        #   status         → SUCCESS/PROCESSING/CLOSED
        ...
        return {
            "success": True,
            "refund_no": refund_id,
            "amount": amount,
        }
```

**配置：**

```ini
PAYMENT_PROVIDER=wechat
WECHAT_PAY_MCH_ID=1900000000
WECHAT_PAY_APP_ID=wx...
WECHAT_PAY_API_V3_KEY=...
WECHAT_PAY_CERT_SERIAL_NO=...
WECHAT_PAY_PRIVATE_KEY_PATH=/path/to/apiclient_key.pem
```

**注意：**
- 微信支付金额单位是**分**，我们系统是**元**，要乘 100
- 回调必须是 HTTPS + 公网可达
- 退款是异步的，`PROCESSING` 状态需要轮询或等退款通知

### 接支付宝

**参数映射：**

| 我们 | 支付宝 |
|---|---|
| `order_no` | `out_trade_no` |
| `amount` | `total_amount`（元，不用转分） |
| `refund_no` | `out_request_no`（退款请求号，必须唯一） |

**配置：**

```ini
PAYMENT_PROVIDER=alipay
ALIPAY_APP_ID=...
ALIPAY_PRIVATE_KEY=...
ALIPAY_PUBLIC_KEY=...
```

### 退款流程（已实现，不用改）

```
用户申请退款
  ↓ POST /refunds
校验 5 条规则（订单状态、金额、重复、时效）
  ↓
创建 refunds 记录（pending）
  ↓
后台审核
  ↓ POST /refunds/{no}/review {approve: true}
调 adapter.refund()
  ├→ 成功 → status=refunded，记 external_ref
  └→ 失败 → status=failed，记 error_message
              ↓ POST /refunds/{no}/retry 重试
```

**这套业务逻辑跟网关完全解耦，接真网关不用改。**

### 退款金额校验规则

`services/refund_service.py`：

| 规则 | 说明 |
|---|---|
| 订单状态 | 只有 paid / preparing / delivering / delivered / completed 能退 |
| 退款金额 | ≤ 实付金额 − 已退金额 |
| 重复退款 | 同一订单不能有多个 pending/approved 的退款单 |
| 退款时效 | 送达后 30 天内（`REFUND_WINDOW_DAYS` 可改） |
| 权限 | 只有管理员能审核 |

**部分退款：** 审核时可以传 `adjusted_amount` 调整金额。

### 抽象接口

`backend/app/adapters/fulfillment/base.py`：

```python
class FulfillmentAdapter(ABC):
    @abstractmethod
    async def push_order(self, payload: dict) -> dict:
        """
        推送订单给履约方
        返回 {"success": bool, "external_ref": str, "message": str}
        """

    @abstractmethod
    async def parse_callback(self, body) -> dict:
        """
        解析履约方回传的状态
        返回 {"order_no": str, "status": str}
        """
```

### 推送内容（payload 结构）

`services/ticket_service.py` 组装的：

```json
{
  "order_no": "TWL20261021144153F31F",
  "receiver": "李女士",
  "phone": "13900001111",
  "address": "广东省深圳市南山区测试路 1 号",
  "delivery_date": "2026-10-22",
  "delivery_slot": "18:00-20:00",
  "card_message": "生日快乐",
  "items": [
    {"product_id": "TW-001", "name": "晨光序曲", "qty": 1}
  ]
}
```

### 接顺丰同城 / 达达 / 闪送

**通用流程：**

1. 注册服务商账号，拿 API Key
2. 写 `adapters/fulfillment/shunfeng.py`（或 dada.py / shansong.py）
3. 实现 `push_order` 把上面的 payload 映射成对方要的格式
4. 在对方后台配置回调地址：`https://你的域名/api/v1/deliveries/callback`
5. 实现 `parse_callback` 把对方的状态映射成我们的

**状态映射示例：**

| 我们 | 顺丰 | 达达 | 闪送 |
|---|---|---|---|
| `sent` | 已下单 | 待接单 | 已发单 |
| `accepted` | 已接单 | 已接单 | 骑士已接单 |
| `delivering` | 配送中 | 配送中 | 配送中 |
| `delivered` | 已送达 | 已完成 | 已送达 |
| `failed` | 已取消 | 已取消 | 已取消 |

### 接自有配送团队

**如果配送是自己人做的：**

**方案 A：不改适配器，用后台手动推进**

```
后台 → 配送管理 → 重推（或跳过推送）
后台 → 订单 → 推进（preparing → delivering → delivered）
```

**现状已经支持。**

**方案 B：写一个 `ManualFulfillment` 适配器**

```python
class ManualFulfillment(FulfillmentAdapter):
    """人工履约：推送时什么都不做，只记一条配送单"""

    async def push_order(self, payload):
        return {
            "success": True,
            "external_ref": "MANUAL-" + payload["order_no"],
            "message": "人工履约，等待后台推进",
        }

    async def parse_callback(self, body):
        return {
            "order_no": body["order_no"],
            "status": body["status"],
        }
```

配 `.env`：

```ini
FULFILLMENT_PROVIDER=manual
```

### 配送状态与订单状态的联动

**这是系统的核心设计：**

```
订单 paid
  ↓ POST /deliveries/notify
推履约 → 订单自动变 preparing
  ↓ 履约方回调 status=delivering
订单自动变 delivering
  ↓ 履约方回调 status=delivered
订单自动变 delivered
```

**联动在 `DeliveryService.handle_callback()` 里，状态机白名单校验。**

**如果履约方没回调，后台可以手动推进订单状态（`POST /orders/{no}/status`）。**

### 接阿里云短信

**前置：**
- 申请签名（1-2 天审核）
- 申请模板（1-2 天审核）

**补 `adapters/sms/aliyun.py` 的 `send_code`：**

```python
async def send_code(self, phone: str, code: str) -> bool:
    """调阿里云短信 API"""
    from alibabacloud_dysmsapi20170525.client import Client
    from alibabacloud_dysmsapi20170525 import models as sms_models
    from alibabacloud_tea_openapi import models as open_api_models

    config = open_api_models.Config(
        access_key_id=self.key_id,
        access_key_secret=self.key_secret,
    )
    config.endpoint = "dysmsapi.aliyuncs.com"
    client = Client(config)

    req = sms_models.SendSmsRequest(
        phone_numbers=phone,
        sign_name=self.sign_name,
        template_code=self.template_code,
        template_param=json.dumps({"code": code}),
    )

    resp = await client.send_sms_async(req)
    return resp.body.code == "OK"
```

**配置：**

```ini
SMS_PROVIDER=aliyun
ALIYUN_SMS_KEY_ID=...
ALIYUN_SMS_KEY_SECRET=...
ALIYUN_SMS_SIGN_NAME=你的签名
ALIYUN_SMS_TEMPLATE_CODE=SMS_123456789
```

### 接阿里云 OSS

**补 `adapters/storage/oss.py` 的 `save`：**

```python
async def save(self, file, filename: str) -> str:
    """上传到 OSS，返回公开 URL"""
    import oss2

    auth = oss2.Auth(self.key_id, self.key_secret)
    bucket = oss2.Bucket(auth, self.endpoint, self.bucket)

    key = f"uploads/{filename}"
    bucket.put_object(key, file.file.read())

    return f"{self.public_url}/{key}"
```

**配置：**

```ini
STORAGE_PROVIDER=oss
OSS_ENDPOINT=oss-cn-shenzhen.aliyuncs.com
OSS_BUCKET=你的bucket
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
OSS_PUBLIC_URL=https://你的bucket.oss-cn-shenzhen.aliyuncs.com
```

## 八、出问题看哪里

| 现象 | 排查 |
|---|---|
| 支付回调没进来 | 回调地址是否公网可达？HTTPS 证书有效？ |
| 退款一直 failed | 商户余额够吗？原交易号对不对？`error_message` 有原因 |

| 验证码验不过 | 多进程部署必须用 Redis，内存缓存在 A 进程发的码 B 进程读不到 |
