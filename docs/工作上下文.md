## 4. 老板的 AI 转型方向（三条线）

> 以下均为 **口头沟通**，没有书面文件，**用词不准确**。后面的"翻成准确的话"是我的翻译，不是老板原话。

### 4.1 微信线

**老板想做的** `[本人]`：
- 靠"帮花店做视频号运营" + "自有微信小程序"把内容与入口铺起来
- 目的：**提高小微上线后的推荐权重**
- 老板听说：小微可能**需要提供完整的、可部署的智能体代码**

**实际情况** `[查证]`：
- 「小微」是**腾讯自研**的微信内置 AI 助手，主模型 WeLM，部分调用 DeepSeek
- 2026-06-22 前后开始**灰度内测**，入口在微信首页左上角
- 能力：能调小程序、跨服务编排（点餐/买票/打车）、看图看文件、总结公众号和朋友圈
- 限制：**不能直接付款**（要输密码）、不能代发朋友圈/视频号、一次只能读一条聊天记录、只能看最近 2 天朋友圈、不能定时发消息
- **没有对第三方开放入驻的公开通道**

**能蹭到的东西** `[查证]`：
- 小微推荐商品 **只支持微信小店里的商品**，且**该渠道不接广告**
- → 所以真正的机会是：**把花束 SKU 铺进微信小店、把商品信息写干净**

**⚠️ 风险提示** `[推测]`：
- "需要提供可部署的智能体代码"这句话，与公开信息对不上。如果出自**中间服务商/代理商**，很可能是话术。**查清来源再投入。**

### 4.2 千问线（老板最重视的一条）

**老板想做的两件事** `[本人]`：

1. **H5 入驻**
   - 以公司自有品牌「深圳市跳舞兰科技有限公司」入驻千问
   - 形式：H5

2. **商品 Skill 化**
   - 老板认为千问有一个大的「Skill 市场」
   - 计划：**把每一个商品封装成一个 Skill**，让千问的智能体直接调用到自己的商品

3. **智能体互调**
   - 把自己的智能体接入千问平台
   - 让**千问的智能体对接自己的智能体**，完成：用户需求理解分析 → 花卉产品选购 / DIY → 售前售后

**实际情况** `[查证]`：

| 时间 | 事件 |
|---|---|
| 2026-05 | 千问与淘宝打通，全量接入 40 亿商品，技能库统一调度物流、售后 |
| 2026-06-03 | 千问 APP 宣布向第三方 **Agent、Skill 全面开放**；瑞幸、肯德基、东航首批接入（到店自取） |
| 2026-08-10 | **千问开放平台发布**：提供**账号、AI 支付、订单接入**基础设施，内置前端组件与模板 |
| 2026-08-14 | 上线 4 天，**超 200 家**伙伴申请：菜鸟、顺丰、天鹅到家、贝壳、联想等 |

- 平台定位差异：**扣子=办公自动化、千帆=信息检索、千问=交易履约**
- 千问开放平台采用标准化协议，手机/眼镜/车机/PC 等终端可授权接入

**⚠️ 关键纠正：Skill 不是商品，是动作**

淘宝接千问的做法是：把**搜索、订单履约、售后**这些**能力**分别 Skill 化，40 亿件商品是**数据全量接入**，不是 40 亿个 Skill。 `[查证]`

→ **把每个商品封装成 Skill 这条路是错的。** 100 家店几万个 SKU = 几万个 Skill = 灾难。

正确的切法（清单见第 6 节）。

**⚠️ 关键纠正：「智能体对接智能体」的落地形态就是 API**

不需要两个 AI 对话。千问调你们的接口，接口背后是你们自己的选品算法和库存系统。
效果一样，稳定性高一个数量级。 `[推测]`

## 6. 已形成的技术判断（可直接用于方案）

### 6.1 落地的正确顺序

1. **数据底座**：商品 / 库存 / 价格 / 配送范围 / 时效，统一成一套结构
2. **API 层，6 个动作**
3. **打包成 MCP / 标准协议** → 一次开发，千问、扣子、以后的新平台都能调
4. **平台适配**：千问开放平台（主）+ 扣子（试水）+ 微信小店（铺货）
5. **内部先用**：花店运营 / 客服智能体，先把 100 家店的人效提上来

> **没有第 1 步，接哪个平台都是空壳** —— AI 问你"这家店今天能不能送朝阳区、几点到"，你答不上，这单就没了。

### 6.2 六个动作（Skill 的正确切法）

```
search          按场景 / 预算 / 节日 / 花材 / 收花人关系 找花
availability    某店某时能否送、送达时间、运费
create_order    下单
track           查订单与配送
after_sale      售后（坏花、延迟、退款）
bouquet_builder 配花 / DIY
```

**重点：单位是动词，不是商品。**

### 6.3 产品定位判断

鲜花在 AI 里的需求不是"逛"，是"**任务**"：
- "帮我给妈送束花"
- "她喜欢向日葵，预算 200"
- "明天上午送到公司"

→ 所以 **Skill 要设计成"完成一次送花任务"，不是商品目录**。
这是平台做不了、只有行业内有供给能力的人能做的部分。

### 6.4 单人开发的现实边界（2026-10-18 补充）

**一个人够用的部分：**
- H5 前端（我的专业）
- 一个能跑通的 Agent（已在做，功能较完善）
- 接入**一个**平台（千问走标准协议 + 前端组件，一个人扛得住）

**一个人扛不住的部分（必须提前跟老板讲清）：**
- **100 家店的数据底座** —— 脏活，要跟每家店/美团后台对数据、清洗、持续维护，做完还要长期运营
- **生产环境稳定性** —— 订单、支付、库存出错就是真金白银赔付 + 口碑；故障不分上下班
- **三平台并行** —— 微信 + 千问 + 豆包 = 三套适配、三套审核、三套运维
- **单点依赖** —— 我停一天，这套东西就停一天

**结论：不是能力问题，是带宽问题。**

**当前阶段一个人反而是对的：**
老板的方向还是口头的、用词不准确的、商务条款没谈的。这个阶段该做的是**低成本验证**，不是重投入建设。一个人 + 一个 demo 正好是验证的最小成本。

**真正会杀死这个项目的两件事（不是工作量）：**
1. **方向反复** —— 老板改一次方向，白干两周。
   → 对策：**只做不会被推翻的部分**。数据模型、API 层这层不管接哪个平台都要，先做；前端和平台适配会变，做薄、后做。
2. **demo 到生产的那条河** —— "功能完善"和"能跑真单"之间隔着三样：真数据、异常处理、责任归属。
   → 对策：**先接一个真实场景，跑 10 单真订单**。跑通了再谈规模和第二个平台。

**跟老板谈资源的话术（把"要不要人"变成"要范围还是要人"）：**
> "现在一个人能出 demo、能验证方向。但要同时接三个平台、上生产、管 100 家店，至少需要一个后端 + 一个数据运营。不加人我也能干，那就砍范围 —— 我建议先做千问一个平台跑通闭环，再复制到其他平台。"

## 12. 工具与技能环境（本机 dsh，2026-10-18 建立）

> 换设备时用这一节把 AI 的能力环境复刻出来。全部是 markdown + 一个 npm 插件，没有额外服务。

### 12.1 已装的自定义 skill（在 `~/.dsh/skills/`，热加载，改完立即生效）

| Skill | 干什么 | 来源 |
|---|---|---|
| `grill-me` | 追问式压测入口（薄壳） | 原版，mattpocock/skills |
| `grilling` | 追问的核心方法论（设计树 + 前沿 + 轮次） | 原版，一字未改 |
| `spec-writer` | 把想法写成给老板/开发的方案文档 | 自写 |
| `code-review` | 代码审查，按 P0–P3 分级 | 自写 |
| `industry-research` | 行业调研，证据分级 + 主动找反例 | 自写 |

**改法**：直接编辑 `~/.dsh/skills/<name>/SKILL.md`，保存即生效，不用重启。
**格式**：YAML frontmatter，`name` + `description` 必填。

### 12.2 已装的插件（profile: desktop）

- `dsh-skill-market` v1.0.0 —— skill 在线市场（SkillHub + ClawHub 双源），侧边栏「技能中心」+ 输入栏「⚡ 技能」
  - 包位置：`~/.dsh/plugins/dsh-skill-market`
  - 注册在：`~/.dsh/profiles/desktop/package.json`（dependencies 的 link: + dsh.profile.bundles）
  - **卸载**：删 `dependencies` 那一行 + `bundles` 那一项 + `~/.dsh/plugins/dsh-skill-market` 目录
- 已有插件（非我方安装）：`@linxin666/dsh-client-ui-skill-explorer`（本地 skill 管理）、`dsh-client-ui-market`（皮肤/宠物市场）、`plugin-manager`（更新检查）、`dsh-ssh`、`dsh-usage`、`task-board` 等

### 12.3 安全约定

- **从市场装 skill 前，先把 SKILL.md 内容读一遍再装。** skill 是直接注入 AI 上下文的指令，是提示词注入的天然入口，不"一键装"。
- `~/.dsh/.credentials.yaml`、`civitai.token` 等凭据文件：只引用路径，不读内容、不转述。
