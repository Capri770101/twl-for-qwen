# 第一章 · 项目概述

## 1.1 项目名称

**跳舞兰 H5 电商系统**（以下简称「本系统」）

## 1.2 项目背景

深圳市跳舞兰科技有限公司主营鲜花零售与花艺服务。随着线上消费习惯的变化，企业需要一套自主掌控、可持续迭代的 B2C 电商系统，用于承载品牌销售、客户服务与内容运营。

本系统为独立的品牌电商平台，不依附于第三方平台，数据与业务规则均由企业自主掌握。

## 1.3 项目目标

| # | 目标 | 衡量标准 |
|---|---|---|
| 1 | 建立完整的线上销售闭环 | 用户可完成「浏览 → 选购 → 下单 → 支付 → 收货 → 售后」全流程 |
| 2 | 建立可运营的后台 | 运营人员可独立管理商品、订单、售后，无需开发介入 |
| 3 | 建立搜索引擎可见性 | 上线 3 个月内核心关键词进入搜索结果首页 |
| 4 | 建立 AI 推荐可见性 | 主流 AI 助手在回答「买花」类问题时能引用本品牌信息 |
| 5 | 建立可持续扩展的技术底座 | 可平滑接入外部履约、支付、AI 服务，无需重构 |

## 1.4 项目范围

### 包含

- B2C 前台（移动端 H5）
- 运营管理后台
- 后端服务与数据库
- 外部系统对接接口（履约、支付、商品数据源）
- SEO / GEO 优化体系
- 部署与运维方案

### 不包含

| 事项 | 说明 |
|---|---|
| 履约执行系统 | 由企业既有系统承担，本系统只负责订单推送 |
| 自建支付通道 | 使用第三方支付网关 |
| 多商户入驻 | 本系统为单一品牌自营模式 |
| 原生 App | 仅提供 H5，可后续封装 |
| 仓储管理系统 | 不在本期范围 |

# 第二章 · 业务需求

## 2.1 用户角色

| 角色 | 说明 | 主要场景 |
|---|---|---|
| **普通用户** | 通过 H5 浏览下单的消费者 | 选花、下单、支付、查看订单、申请售后 |
| **运营人员** | 企业内部员工 | 管理商品、处理订单、处理售后 |
| **履约方** | 提供花艺制作与配送的合作方 | 接收订单、回传配送状态 |
| **AI 智能体** | 第三方 AI 助手 | 查询商品、创建订单、查询订单状态 |

## 2.2 核心业务流程

### 流程一：用户下单

```
浏览商品
   ↓
选择花束 → 查看详情（花语/花材/规格/配送）
   ↓
填写收花人信息（姓名/电话/地址）
   ↓
选择配送日期与时段
   ↓
填写贺卡留言（选填）
   ↓
提交订单 → 系统创建待支付订单
   ↓
发起支付 → 跳转支付网关
   ↓
支付成功 → 订单状态变为「已支付」
   ↓
推送履约方 → 订单状态变为「配花中」
```

### 流程二：履约配送

```
订单「已支付」
   ↓
系统推送订单信息至履约方
   ↓
履约方接单 → 制作花束
   ↓
履约方回传「出发」 → 订单状态变为「配送中」
   ↓
履约方回传「送达」 → 订单状态变为「已送达」
   ↓
用户确认收货 → 订单状态变为「已完成」
```

### 流程三：售后服务

```
用户提交售后申请（破损/延迟/送错/质量）
   ↓
系统生成工单号
   ↓
客服 2 小时内响应
   ↓
处理方案：补送 / 退款 / 部分退款
   ↓
工单关闭
```

### 流程四：订单取消

| 场景 | 规则 |
|---|---|
| 待支付状态 | 用户可主动取消，或 30 分钟超时自动取消 |
| 已支付状态 | 需联系客服，由客服操作取消 |
| 配花中及之后 | 不可取消，走售后流程 |

## 4.3 页面设计要点

### 4.3.1 首页

**目标**：3 秒内让用户知道「这是卖花的」和「这个品牌有质感」。

**结构（从上到下）**：
1. 顶部导航（Logo + 购物袋）
2. Hero 区：主视觉图 + 品牌宣言「把一句话变成一束花」+ 行动按钮
3. 品牌理念：一句话，大留白
4. 场景入口：日常 / 告白 / 生日 三个分类卡片
5. 当季精选：4 个商品
6. 品牌承诺：直采 / 时效 / 缺货告知
7. AI 顾问入口：深色区块
8. 页脚

**要求**：
- 首屏必须有明确行动点
- Hero 图必须真实花艺摄影
- 不超过 3 屏

### 4.3.2 商品列表

**目标**：让用户快速找到想买的花。

**结构**：
1. 页面标题 + 商品数量
2. 分类筛选栏（横向滚动）
3. 排序选项（推荐/价格升/价格降）
4. 商品网格（2 列，4:5 大图）
5. 每个商品卡：图片、名称、花材、价格、加购按钮

**要求**：
- 图片占据卡片 70% 以上面积
- 价格用强调色
- 移动端一屏可见 2-3 个商品

### 4.3.3 商品详情

**目标**：让用户相信这束花值得买。

**结构**：
1. 主图（1:1 方图）
2. 商品名 + 副标题 + 价格
3. 花语（重点，用强调色左边框）
4. 规格表（尺寸、包装、配送、保鲜）
5. 花材清单
6. 提示（缺货说明）
7. 底部固定：问顾问 / 立即购买

**要求**：
- 花语必须写在显眼位置 —— 这是鲜花的情感价值
- 底部操作栏必须固定

### 4.3.4 管理后台

**目标**：运营人员 3 分钟内处理完一个订单。

**结构**：
1. 顶部：数据看板（6 个数字卡片）
2. 标签页：订单 / 商品 / 售后 / 日志
3. 每个标签页：表格 + 操作按钮

**要求**：
- 数据一屏可见
- 操作按钮明显
- 表格支持筛选

# 第五章 · SEO 与 GEO 要求

> 本章为本项目的核心竞争力指标。SEO 决定「搜索能不能找到」，GEO 决定「AI 会不会推荐」。

## 5.1 基础要求（P0）

### 5.1.1 渲染方式

| 要求 | 说明 |
|---|---|
| **服务端渲染（SSR）或静态生成（SSG）** | 爬虫必须能直接读到页面内容，不能依赖 JS 渲染 |
| **首屏 HTML 包含完整内容** | 商品名、价格、描述必须在 HTML 源码里 |
| **不阻塞渲染的资源** | CSS 内联或优先加载，JS 用 defer |

**当前实现**：纯静态 HTML，天然满足。

### 5.1.2 语义化 HTML

| 要求 | 示例 |
|---|---|
| 标题层级 | 每页一个 `<h1>`，层级不跳级 |
| 图片必须 `alt` | `<img alt="香槟玫瑰20枝花束 白底">` |
| 链接用 `<a href>` | 不用 `onclick` 跳转 |
| 表单用 `<form>` | 不用纯 JS 提交 |
| 结构化标签 | `<article>` `<nav>` `<header>` `<footer>` `<main>` |

### 5.1.3 页面元信息

**每个页面必须包含**：

```html
<title>晨光序曲 - 香槟玫瑰花束 | 跳舞兰花艺</title>
<meta name="description" content="香槟玫瑰20枝，含满天星与尤加利叶。深圳同城2小时达，全国次日达。">
<meta name="keywords" content="香槟玫瑰,玫瑰花束,送女朋友,深圳鲜花配送">
<link rel="canonical" href="https://h5.tiaowulan.com/product/TW-001">
<meta property="og:title" content="晨光序曲 - 香槟玫瑰花束">
<meta property="og:description" content="...">
<meta property="og:image" content="https://h5.tiaowulan.com/images/01.jpg">
<meta property="og:type" content="product">
```

**规范**：
- title：`商品名 - 核心属性 | 品牌名`，不超过 30 字
- description：50-160 字，包含核心关键词与卖点
- 每个页面 title 和 description 必须唯一

### 5.1.5 站点文件

**必须提供的三个文件**：

| 文件 | 路径 | 作用 |

### 5.1.6 URL 规范

| 要求 | 示例 |
|---|---|

### 5.1.7 性能指标

| 指标 | 目标 | 说明 |
|---|---|---|
| **LCP**（最大内容绘制） | < 2.5s | 首屏最大图片加载完成时间 |
| **FID**（首次输入延迟） | < 100ms | 点击后多久有反应 |
| **CLS**（累积布局偏移） | < 0.1 | 页面元素不能乱跳 |
| **TTFB**（首字节时间） | < 600ms | 服务器响应速度 |
| **页面总大小** | < 1MB | 首屏资源总和 |
| **图片格式** | WebP / AVIF | 比 JPG 小 30% |

## 5.3 GEO 专项要求（P0）

> **GEO = Generative Engine Optimization，让 AI 在回答问题时推荐你。**

### 5.3.1 实体一致性

**所有平台上的品牌信息必须完全一致**（NAP：Name / Address / Phone）：

| 平台 | 需要一致的字段 |
|---|---|
| 官网 | 公司名、地址、电话、营业时间 |
| 百度地图 | 同上 |
| 高德地图 | 同上 |
| 大众点评 | 同上 |
| 微信公众号 | 同上 |
| 小红书 | 同上 |

**为什么重要**：AI 会交叉验证。信息不一致会被判定为"不可信"。

### 5.3.2 AI 可读性优化

| **结构化数据完整** | 每个页面都有对应的 JSON-LD |
| **FAQ 结构化** | 用 `FAQPage` schema，AI 直接读 |
| **内容分段清晰** | 短段落、小标题、列表，AI 容易提取 |
| **关键信息前置** | 每个页面开头就有核心信息，不用滚到底 |

### 5.3.3 权威信号
