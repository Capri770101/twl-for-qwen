## frontmatter 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `slug` | ✅ | URL 里的英文名，全小写，用连字符 |
| `title` | ✅ | 文章标题，包含核心关键词 |
| `category` | ✅ | 分类：rose / tulip / sunflower / hydrangea / camellia |
| `meaning` | ✅ | 花语一句话，显示在列表页 |
| `cover` | 建议 | 封面图，用 `/images/xxx.png` |
| `tags` | 建议 | 标签数组，用于关联推荐 |
| `status` | ✅ | `published`（发布）/ `draft`（草稿） |
| `sort_weight` | 否 | 排序权重，数字越大越靠前 |
| `seo_title` | 建议 | SEO 标题，可以和 title 不同 |
| `seo_description` | 建议 | SEO 描述，50-160 字 |

## 写作要求

### 1. 开头必须有一句话答案

**为什么：** AI 引用你的内容时，最可能引用的就是开头这一句。

```markdown
香槟玫瑰的花语是**「爱上你是我今生最大的幸福」**。它适合送女朋友、妻子、母亲...
```

**不要这样：**
```markdown
玫瑰花是很多人喜欢的花。香槟玫瑰作为一种特殊的玫瑰...
（绕了 100 字才说花语是什么）
```

### 2. 每篇 800-1200 字

太短没内容，太长读者看不完。

### 3. 必须有具体数字

**好：**
- 「深圳同城 2 小时达，16:00 前下单当日送达」
- 「含保鲜剂常温可养 5-7 天」
- 「斜剪根部 1-2cm」

**不好：**
- 「很快送达」
- 「能养挺久」
- 「剪一下根」

### 4. 每篇结尾有 3-4 个 FAQ

用 `### 问题？` 的格式，脚本会自动提取成结构化数据。

**FAQ 怎么找：**
- 客服真实遇到的问题
- 百度「相关搜索」
- 小红书评论区的提问

### 5. 内链到商品

正文里提到某款花束时，自然地带个链接：

```markdown
用香槟玫瑰做的花束有[晨光序曲](/product.html?id=TW-001)，¥299。
```

## 不能做的事

| ❌ 不能 | 为什么 |
|---|---|
| 编造成立年份 | 会被查证，损害信任 |
| 编造销量/客户数 | 同上 |
| 编造客户评价 | 违法违规 |
| 抄别人的文章 | 侵权，而且 SEO 会判定重复内容 |
| 写「行业第一」「最好的」 | 广告法禁止绝对化用语 |
| 写无法验证的疗效（如「能治病」） | 违规 |

## 写作流程

### 1. 选选题

从 `选题清单.md` 里挑，或者从真实客户提问里找。

### 2. 查资料

- 花语：查维多利亚花语体系、中国传统花语
- 养护：园艺常识，可查证
- 数据：用门店真实数据

### 3. 写初稿

按模板填，30-40 分钟一篇。

### 4. 导入

```bash
cd scripts
python import_content.py
```

### 5. 检查

打开 `http://127.0.0.1:8000/flower-language.html` 看效果。

### 6. 更新 sitemap

```bash
python gen_site_files.py
```

## 内容来源的三层

### 第一层：公开资料（打底）

- **维多利亚花语体系** —— 西方花语的源头，公开资料多
- **中国传统花语** —— 如「梅兰竹菊」，有大量文献
- **园艺常识** —— 养护方法、花期、品种

**用法：** 这些是「事实」，可以直接写，但最好标注来源。

### 第二层：门店经验（护城河）

**这是别的花店抄不走的：**

- 100+ 家门店的销售数据 → 哪款花卖得最好
- 花艺师的实战经验 → 客户最常问什么
- 售后工单统计 → 最常见的三个问题

**用法：** 用「我们发现」「根据门店数据」这样的表述。

### 第三层：客户提问（FAQ 来源）

- 客服聊天记录
- 美团评价里的问题
- 群里的提问

**用法：** 脱敏后直接变成 FAQ。

## 内容质量标准

一篇文章写完，问自己四个问题：

1. **有没有一句话能回答标题的问题？**（AI 引用）
2. **有没有具体数字？**（可信度）
3. **有没有 3 个 FAQ？**（GEO 加分）
4. **有没有内链到商品？**（转化）

四个都有，就是合格的文章。
